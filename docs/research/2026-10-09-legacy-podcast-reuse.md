## Recommended native adapter contract

Add stable shared types in `packages/core/src/lickety/podcast-types.ts`. Store an explicit, versioned `PodcastAssemblyState` under `Project.lickety` with a persisted `setupId`, confirmed groups, ordered segment media IDs, stream/channel selection, participants, microphone modes, sync mappings/regions, confidence/status, evidence identity, manual notes, and approval revision/digest. Map each legacy inventory `assetId` to the existing stable `MediaItem.id`; retain originals through the current `nativeSource`/asset registry. Analysis records may keep source stream indices and source-time facts, but portable project state must not depend on legacy absolute paths.

Keep the IPC contract identity-based: accept `projectId`, `setupId`, imported `mediaId`s, and validated source groups; never accept renderer-supplied filesystem paths. For prompt inventory, resolve `ManagedAssetRegistry.originalUri(mediaId)` to its opaque reference and inspect through the registered original; that path does not need a content hash for every imported file. When the user requests sync analysis, call `findMedia(mediaId)`/`registerOriginal()` for only those selected sources, then use its opaque `RegisteredAsset.identity.assetId` plus digest for work/cache identity. Return portable inventory, placements, review evidence and opaque media/source IDs only; do not return original paths or PCM to renderer. Reject unknown registry IDs and media not present in the submitted setup. This keeps path authority in the main process while letting the renderer associate placements with existing media-library items.

The adapter should take that saved setup plus resolved native media IDs and return one native edit payload: source `Track`s and per-file `Clip`s with original `mediaId`, exact source `inPoint`/`outPoint`, episode `startTime`/duration derived from the saved mapping, microphone `audioTrackIndex`, dialogue role and participant binding, grouped camera metadata, and the updated `lickety` state. Apply it with the existing single undoable timeline/multicam/project operation. Missing/unresolved segments require an explicit user placement or exclusion before final creation; gaps remain gaps. A completed camera angle is an ordered set of original-source clips, not a concatenated derivative.

Native seam to preserve: `CameraAngle` in `packages/core/src/video/multicam-engine.ts` currently stores one `clipId`; `buildSequenceClips`/`buildShotPlanTracks` resolve that one source clip. Add an optional ordered `sourceSegments` mapping (clip/track IDs plus episode coverage) and keep the existing single-clip path intact. Source clips stay native timeline clips on the camera track; the angle planner consumes the grouped segment manifest. Dialogue microphones become `role: 'dialogue'` tracks with actual participant/channel metadata; scratch stays distinct and muted as program audio. This supports current playback/export and reuses the project’s current track/clip behavior.

## Dependency and evidence limits

- `electron/intake.ts` combines pure grouping with Node `fs`, `child_process`, packaged `ffprobe`, timestamp scanning, XML escaping, and file writing. Extract/reuse pure grouping and keep inspection in desktop main; do not import the whole module into the renderer. `buildIntakeXml()` and `buildWaveXmlIntake()` are the replaceable XML boundary.
- The unsafe-to-copy seam is `electron/sync-cache.ts` `extractChannels()`: it hashes source paths, launches the standalone `cutline-audio-decode` helper over the entire recording, writes a complete interleaved 8 kHz float PCM file per stream, then reads 32.768-second feature blocks plus 4 seconds of context on both sides. That bypasses the fork’s existing job queue and violates the <=10-second audio-window rule. The legacy matcher itself uses <=6-second fine windows, so keep `fingerprintBlock`, `coarseCandidates`, `fineCorrelation`, `fitClock`, `solveGraph`, validation/abstention, revision and cache-checksum semantics; replace only full-file decode/read with incremental windows.
- Minimal safe read path: invoke main-process `NativeAudioAnalysis.getNativeAudioWindow()` directly with its registered opaque asset ID, source stream ordinal and 8 kHz sample rate. The method already accepts <=10,000 ms, resolves through `ManagedAssetRegistry`, and acquires `heavyQueue`; a 10-second mono 8 kHz window is 320 KiB. Its renderer IPC schema currently allows only 1,000/16,000/48,000 Hz, but this sync service should stay main-side and avoid sending PCM over IPC. Preserve per-source-channel extraction: do not downmix multichannel camera/mic tracks into one mono signal; add a channel selector/pan extraction to the bounded reader where the source has more channels than the returned stereo lanes. Read sequential <=10-second windows with bounded overlap sufficient for the 512-sample FFT and hash timing; preserve stream start PTS/discontinuities, checkpoint between calls, and cache checksummed feature summaries. Each native read goes through `heavyQueue`; do not hold `heavyQueue.run()` around an orchestration that calls `getNativeAudioWindow()` because that method itself acquires the same queue. Run fingerprinting and matching in main and report progress/results only.
- Current desktop `inspectOriginal()`/`probeInputHeader()` provide fast basic metadata behind the existing queue, but do not synthesize a verified continuous packet-timing receipt. Keep import/group suggestions fast and metadata-only; defer identity hashing, audio features and packet/timestamp checks until the selected source is actually lined up. If timestamp coverage/discontinuities are unsupported or absent, preserve that as unknown/needs-review; do not manufacture a continuous source clock.
- `electron/sync-engine.ts` is not a standalone browser module: it imports the above PCM/cache code, `mediaCheckpoint`, timestamp scanning, DSP, graph/region/validation modules, and legacy project types. Keep reusable DSP/graph/project semantics in the desktop main boundary, adapt channel/window providers to the bounded native reader and existing scheduler, and key caches by opaque registered source identity, stream facts, algorithm/feature version and analysis parameters. Do not carry absolute source paths into portable setup/results.
- Legacy unit fixtures are mostly generated in-memory metadata/PCM and temporary files. They verify algorithm and state transitions, but do not prove split-file playback in a real episode, one-hour drift, native project save/reopen/relink, Create timeline undo, or React flow behavior. `sync-audio-lanes.test.ts` specifically exercises the XML renderer. Rebuild these as native adapter regressions rather than carrying over XML assertions.
- Not run: `scripts/verify-native-intake.ts` and `scripts/verify-sync-native.ts`; those are native/helper integration checks with generated on-disk media and custom helper paths, beyond this focused unit baseline. No owner media or app profile was opened.
